# build-what-moves-india (Avsar)

Opportunity-finder portal for the Build What Moves India hackathon (Varun Mayya × OpenAI, submission 27 Aug 2026, finale 12 Sep). Repo `vaibhavgit9210/build-what-moves-india`, **live at https://avsar.pages.dev/** (Cloudflare Pages project `avsar` on the vaibhavpro9210 account; deploy = `npx wrangler pages deploy <dist with index.html,data.js,health.json> --project-name avsar --branch main`). The old GitHub Pages URL (https://vaibhavkumar.is-a.dev/build-what-moves-india/) still deploys from `gh-pages` but JS-forwards to avsar.pages.dev preserving the hash — so a deploy is THREE pushes: `main`, `main:gh-pages`, and wrangler pages deploy. The beacon sends page `/avsar/` on pages.dev to avoid colliding with the portfolio homepage's `/` in site-analytics.

**Hackathon compliance note:** the brief mandates Codex/OpenAI-model involvement in the build — that's the user's call to reconcile before submitting; don't misrepresent tooling in any write-up.

## Shape

- `index.html` — the whole app (no build, no CDN, system fonts, works from `file://`). All data rendered via `createElement`/`textContent`, never innerHTML. Filter state lives in `location.hash` → every filtered view is a shareable URL. Two views: the list, and an **exam detail page** at `#exam=<id>` (optionally `&sec=syllabus|papers|pattern|keys|mock|notification` to highlight a preparation section). `body[data-view="detail"]` hides the list.
- `data.js` — `window.AVSAR_DATA = {updated, examsVerifiedAt, opportunities:[...]}`, 164 entries, the single source of truth. Base schema (every entry): id/name/category/oneLiner/ageMin/ageMax/minEducation(any|10th|12th|diploma|ug|professional|pg)/feeINR(null=varies, fails fee-cap filters on purpose)/benefit/window/windowMonths(1-12, []=rolling)/nextExpected/frequency/official/resources(≤3)/tags. Eligibility numbers are GENERAL-category. Dataset was researched + adversarially verified by a 15-agent workflow (Aug 2026); wrong official URLs are the worst failure mode — verify before editing one.
- **46 of those entries are `type:"exam"`** and carry the exam layer on the same object: organization (one of the 17 filter keys) / organizationFull / typicalJobs / description / officialWebsite / officialExamPage / status (`open|upcoming|closed|not-announced|exam-completed`) / statusNote / notification{title,date,cycle,current,pdfUrl,url,embeddable} / extraNotifications / application{openingDate,closingDate,url} / examDate / expected{notificationDate,closingDate,examDate,source,sourceUrl} / eligibility{education,age,other} / fee / syllabus / examPattern{summary[],title,url} / pastPapers[{year,papers[{name,url}]}] / answerKeys / mockTests / the matching `*Note` and `*Page` fallbacks / source / verifiedAt. **Deliberate deviation from a naive reading of the spec:** numeric eligibility stays in the existing top-level `ageMin`/`ageMax`/`minEducation`/`feeINR` (that is what the filters read); `eligibility` holds only the plain-language strings, so no number is stored twice.
- `health.json` — written weekly by `.github/workflows/data-health.yml` (runs `scripts/check_links.py`, stdlib-only, 8-thread pool, 511 URLs in ~70s). 403/405/999 = alive-but-blocked and `TLSV1_ALERT_PROTOCOL_VERSION` = client-side TLS limitation — neither is a failure. The script also validates the exam records (duplicate ids/names, unknown organization or status, malformed or contradictory dates, an `open` exam with no deadline or notification) into `health.json.dataIssues`. The Action commits to main AND pushes main:gh-pages, and opens/updates a GitHub issue. This is the keyless "updates itself" story.
- `worker/` + `PLAN-V2.md` — **staged, not deployed** V2: `avsar-live` Cloudflare Worker (would go on vaibhavpro9210 account) serving a `/overlay`. The frontend's `withLive()` overlays exactly four fields onto an exam record — status, application deadline, application URL, notification URL — and labels `confidence:"auto"` values as auto-extracted. Frontend hook: `LIVE_ENDPOINT` const in index.html, currently `null`.

## Gotchas

- Categories are 6 fixed keys (`college gov-job scholarship abroad private-job resource` — gov-exam was merged into gov-job); colors are `--c-<key>` CSS vars with light/dark/colorblind (Okabe-Ito) variants, and each has a text glyph so color is never the only signal.
- Screenshot hooks: `#shot=home|dark|cb|filtered|exam|prep`; any real filter hash works too (`#age=17&edu=12th&cat=college`, `#org=UPSC&status=open`, `#exam=ssc-cgl`, `#lang=ta`). Static page, no rAF — but the beacon's `setInterval` means headless Chrome needs `--timeout` not just `--virtual-time-budget` when loading over http (fine over `file://`, beacon exits early there). **Headless Chrome clamps the viewport to ~500px minimum**, so a 390px screenshot looks like it overflows when it doesn't — check `document.documentElement.scrollWidth` instead of trusting the image.
- The month filter and "soonest to apply" sort read `windowMonths`; `[]` means rolling and matches every month. `sorted()` puts `type:"exam"` entries first (then open → upcoming → closed → exam-completed → not-announced), so the rest of the dataset still shows below.
- **Notification PDFs: `embeddable` is measured, not guessed.** `true` for ssc.gov.in / ibps.in / cdnbbsr.s3waas.gov.in (CTET) / afcat.edcil.co.in; `false` for upsc.gov.in, rrb.indianrailways.gov.in, sbi.bank.in, sebi.gov.in, licindia.in, gicre.in (DENY), rac.gov.in, isro.gov.in — they all send `X-Frame-Options`. `null` = unknown, so the iframe is tried with a 4s fallback timer. Re-measure with a HEAD request before flipping a flag. Headless Chrome loads the PDF viewer but never paints page content, so an embedded notification always screenshots as a blank dark box — that is not a bug.
- UPSC notification PDFs are **scanned images** (no text layer), so `pdftotext` gets nothing from them; SSC/IBPS/RRB/SEBI notices are text. `rbidocs.rbi.org.in` and AIIMS notice files are bot-protected / time-limited: RBI notifications link the HTML advertisement page as well as the PDF, and AIIMS links only the official page because its file URLs are S3 presigned and expire.
- `UI_TEXT` holds 8 languages (en/hi/mr/kn/ta/te/bn/ml) and `t()` falls back to English per key, so a missing translation never shows a raw key. Official exam names and acronyms are never translated. Language lives in `localStorage` + the `lang=` hash key.
- Regional search works through `ALIASES` (a match on "सरकारी परीक्षा" etc. resolves to the pseudo-term `type:exam`, which matches every exam) and `INTENTS` ("ssc cgl syllabus", "upsc pyq") which strips the intent word from the query and offers a direct link into that section.
